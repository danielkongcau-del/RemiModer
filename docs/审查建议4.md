# 3. SRV 格式和 Resource 格式必须拆开

这是我建议你在捕获规范中再特别强调的一点。

不要只保存：

```text
Texture resource:
R8G8B8A8_TYPELESS
```

而必须同时保存：

```text
Resource:
DXGI_FORMAT_R8G8B8A8_TYPELESS

SRV:
DXGI_FORMAT_R8G8B8A8_UNORM_SRGB
MostDetailedMip = ...
MipLevels = ...

RTV:
DXGI_FORMAT_R8G8B8A8_UNORM
```

同一个底层 resource 可以通过不同 view 被不同语义访问。

如果只恢复 texture，而没有恢复 view：

```text
Linear ↔ sRGB
```

会直接错。

你文档已经意识到 typeless resource 与 SRV view 关系在 JPG/普通导出中可能丢失。

我会把：

> **ResourceDesc 和所有 ViewDesc 是两个独立的 P0 对象**

写进 capture schema。

# 还有一个我会修改的验收标准

你文档现在要求：

> 游戏 Shader 字节码 + 游戏运行时参数 + 游戏固定状态。

这个非常好。

但是最终“动态 Demo”不应该要求：

> 每个中间像素永远等于某个固定游戏帧。

而应该有两种标准：

### Golden mode

```text
固定 camera
固定 pose
固定 CB
固定 resource
```

要求极高数值一致性。

### Interactive mode

```text
新的 camera
新的 pose
新的 animation time
```

没有原版同一帧可以逐像素比较。

此时验收的是：

```text
Renderer identity
+
parameter producer identity
+
behavioral equivalence
```

这两个模式一定要分开。

否则以后你又会掉进：

> “动态情况下无法逐像素证明，所以不能算完成”

这种无终点陷阱。
