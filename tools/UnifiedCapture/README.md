# UnifiedCapture

UnifiedCapture is a configurable local evidence recorder for Windows x64 processes. It is designed around immutable capture generations, bounded callback work, explicit hook ownership, independent loss accounting, and sealed local evidence chunks.

## Components

- `native/` implements the C++20 recorder and owned-fixture executables.
- `uc/` implements schemas, validation, storage verification, indexing, projections, and mechanical callsite analysis.
- `capturectl.py` provides the local control interface.
- `d0ctl.py` and `entryctl.py` provide resumable single-entry and multi-entry orchestration.
- `campaignctl.py` qualifies the union of several entry plans once, then switches their immutable generations in one target process with explicit armed/complete marks.
- `p1_bind_campaign_callsites.py` binds that campaign to mechanically decoded static callsites while preserving unresolved indirect callers for runtime resolution.
- `p1_merge_entry_plans.py` and `p1_reframe_campaign.py` change activation-unit granularity without repeating an already exact physical-site qualification.
- `controller_capture_frontier.py` builds one source-bound causal capture unit from the current closure ledger, role-classified wrappers, Animator stages, bridge ABI, and selected native parameter consumers. It excludes alternate implementation members and chapter-only actions from normal-trial repetition.
- `controller_field_read_plan.py` mechanically enriches that frontier with field-level task/ECS reads and raw parallel-job ABI windows. It verifies harvested field lines, reflected method RVAs, the closed job wrapper type, and selected native instructions before emitting a new immutable plan. The resulting labels remain raw evidence contracts and do not upgrade candidates into object/entity identities.
- `d0_analyze.py` and `entry_analyze.py` validate sealed sessions without promoting stronger claims than the evidence supports. `entry_analyze.py` accepts both legacy flat runs and campaign roots (selecting a unit with `--unit` when necessary), deduplicates caller evidence by return address, and emits only mechanically established PDATA-owned execution edges.
- `checkpoint_delta.py` derives per-point, per-caller cumulative deltas between linked `mark` checkpoints. Its intervals remain explicitly bounded non-atomic snapshots; they are useful for action segmentation but are not presented as perfectly cut event traces.
- `exact_caller_promotion_plan.py` turns callers already discovered in a clean aggregate-retention session into evidence-backed, module-relative exact-capture lanes. A separate selection file only scopes the requested callers; it is never treated as game evidence.
- `retained_caller_inventory.py` validates a sealed retained session and emits a non-selecting inventory of callback counts, module-relative return RVAs and mechanically decoded callsites. It supplies exact-promotion row templates but does not decide which callers are semantically relevant.
- `retained_run_finalize.py` performs the post-stop acceptance, bounded coverage summary and retained-caller inventory as one immutable workflow. It reports readiness for exact selection only when the sealed store, every point and all caller counters pass their independent checks.
- `retained_exact_selection.py` emits a scope-only selection containing every mechanically eligible caller from one clean, complete inventory. It does not assign gameplay meaning; ineligible rows stay explicit in its report.
- `caller_continuation_prepare.py` turns already exact-promoted caller return RVAs into mechanically checked continuation candidates and a target-process qualification request. `caller_continuation_apply.py` binds the patch/restore result back into a process-bound v2 plan. Unsafe or overlapping continuation sets remain entry-only and are reported; no caller is selected or discarded semantically by these tools.
- `entry_analyze.py` streams sealed chunks and retains bounded event-id samples instead of materializing the whole event stream. Its v2 acceptance artifact records whether the sample is complete while preserving exact event counts and representative callsite evidence.
- `tests/` contains generic unit and native-fixture tests.

## Dependencies and build output

`bootstrap.py` downloads fixed public dependencies and verifies their digests. Downloaded dependencies, binaries, plans, target bindings, baselines, and test output are deliberately ignored.

The library is an observation component, not an injector. Target loading is outside this repository. Mutation hooks, protection changes, and target-specific evidence are outside the public scope.

The local duplex control pipe rejects remote clients, grants access only to the creating Windows user and SYSTEM, and carries a medium mandatory label. This permits the normal same-user medium-integrity controller to operate an observer loaded by an elevated launcher without granting write access to low-integrity processes.

## Evidence boundaries

Raw ABI evidence and semantic interpretation are distinct. A decoded callsite is not automatically a semantic caller identity. A type identity is not execution evidence. File integrity is not semantic completeness. Unobserved events remain unknown unless the exact observation point had complete, lossless coverage for the stated window.

## Safety gates and attribution

- Code observation supports instruction probes and evidence-qualified entry/exit probe pairs. Function call listeners are not accepted by either plan schema or the runtime.
- Slot replacement refuses activation under CFG unless the plan explicitly owns the indirect-dispatch risk (`accept_cfg_indirect_dispatch_risk`).
- Read programs support `scalar`/`relative`/`register`/`block`/`array`/`string` operations at explicit `enter` or `leave` phases. `register` copies raw ABI register bits without dereferencing them and may drive an entry predicate. Predicates support `eq`, `neq`, and a bounded `in` set of at most 16 values. Leave reads may use saved entry registers through `entry:<register>`; dependencies must remain within one phase. `when` predicates remain entry-only, and filtered events are counted (`filtered_by_plan`), never silently dropped.
- Entry-only instruction probes may select `first_per_entry_return_address` retention. A fixed, preallocated table counts every classified callback by the architectural entry return address, queues one full ABI/read sample per key, retries that sample if the event pool was temporarily full, and reports key-read or table-capacity failures as loss. Duplicate suppression is deliberate policy, not queue loss.
- When one callsite carries several raw receivers/tasks, `first_per_composite_key` extends that key with up to three masked raw GPR values. The architectural entry return address remains the mandatory first part. The table stores and compares every raw part; its 64-bit fingerprint is only a lookup accelerator and never identity proof. Concurrent unfinished publication is bounded and independently reported as `retention_key_busy` rather than blocking a target thread.
- The same retention policy may list up to 256 evidence-backed `exact_callers` as module-relative return RVAs. Those callers keep exact per-callback records while every other caller remains aggregate-first-sample. Addresses are resolved for each module load generation; raw addresses remain observations, not object or semantic identities.
- A qualified probe-pair may use this policy only when at least one exact caller is listed. Every admitted callback is still aggregated before the gate; unselected callers emit at most an `aggregate_entry_sample`, while selected callers alone allocate PairFrame state and emit exact `enter`/`leave` evidence.
- Completion may come from either a fully verified native callee exit set or an exact caller continuation. A continuation plan must match every exact caller gate one-for-one, prove a unique predecessor `call` from immutable module bytes, prove a whole-instruction relocation window with no decoded direct edge into its interior, and pass target-process patch/restore qualification. At entry, the frame is bound only to the return address actually read from `[RSP]`; another caller's continuation cannot close it. Its evidence means `normal_return_to_observed_callsite_continuation`, never “complete callee exit set.” Exceptional/nonlocal exits remain unknown and are accounted as incomplete frames if later observed absent or at stop.
- After a clean discovery stop, the same still-running process may open a fresh evidence session for continuation-site qualification and then activate the derived plan. Forced or uncertain stops remain terminal; this path does not relax protection, loader, or unsafe-mode policy.
- Retention summaries are cumulative for an activation generation. They establish caller counts and caller discovery only when `complete_for_caller_counts` is true and every key has a persisted full sample; they never claim a complete per-event temporal trace or an exact marked-window distribution.
- Capacity loss is attributed to mutually distinct counters: `record_pool_exhausted`, `store_backpressure`, `pair_frame_capacity`, `thread_nesting_capacity`, `pair_payload_capacity`, and `pair_open_failure`. Read, truncation, persistence, frame-termination, and retention failures retain their own reasons. There is no generic queue-overflow diagnosis. Exact lanes also record the first `exact_coverage_end_qpc`; later records may remain useful, but the stream is permanently `BROKEN_WITH_GAPS` for that generation.
- Status and periodic health checkpoints expose cumulative callback/capture/store counts, per-point record-pool high-water marks, activation-lifetime average rates, store backlog high-water marks, and seal/manifest throughput. Rates are diagnostics derived from QPC; cumulative counters remain the evidence used for deltas.
- Completed cells are published through a preallocated tagged ready-index stack per observation. The worker processes only detached ready batches instead of scanning every reserved cell each tick; `ready_queue_depth` and `ready_queue_high_water` expose that stage independently. Explicit clean stop waits for the ready depth to reach zero.
- `mark` durably appends a `uc.CaptureCheckpoint.v1` record and a linked `user_mark` with the same checkpoint id. The checkpoint contains cumulative loss, retention, point-health, storage, admission-window, and unattributed-storage-loss counters. Callback/capture counters describe observation progress; store counters describe asynchronous processing progress and need not have caught up at the mark. The snapshot records its begin/end QPC and `snapshot_atomic=false`; no exact boundary is invented.
- Native runtime events use the compact binary v3 metadata layout documented in `docs/record-v3.md`; the `.ucb` container continues to identify this binary family as `uc.record.v2`. A hash-chained generation dictionary carries repeated point/read/exit/retention semantics once; `.ucb` remains the evidence original, while the Python decoder reconstructs the existing `uc.event.v1` JSON projection for indices and analyzers. `UCEVT002` and legacy/test `uc.record.v1` chunks remain readable.
- Store seals 32 MiB target segments against a bounded 256 MiB asynchronous backlog, reducing durability barriers by eight relative to the old 4 MiB chunks. XPRESS-HUFF is attempted while the backlog is at most 64 MiB and bypassed above that threshold; the decision and codec totals are recorded, so compression cannot silently become the reason evidence is discarded. A crash may invalidate the final `.partial` segment but does not alter earlier sealed segments.
- Callbacks observed while admission is closed are counted in a durable `admission_window` note.
- Storage failures persist a `storage_error` manifest note including events lost to the failing seal.
- A detected persistence failure closes capture admission and reports `STORAGE_FAILED`; explicit stop still performs independent ownership-aware hook cleanup.
- Manifest lines are hash-chained (`prev_sha256`); deletion or reordering of sealed history is detectable offline.
- `stop --force` performs a terminal unclean seal for wedged frames. Late callbacks keep shared ownership, and hooks/resources that cannot be proved safe to detach remain resident until process exit; the observer refuses reactivation in that process.
- CLI tools share exit-code discipline: 0 ok, 1 observer rejection, 2 internal error.
